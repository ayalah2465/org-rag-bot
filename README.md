# בוט ידע ארגוני (RAG) - תחנות טיפת חלב, מרחב ירושלים

מערכת בוט המאפשרת לעובדי הארגון לשאול שאלות בשפה חופשית על מסמכי הארגון, ועונה **אך ורק** על סמך המידע שנמצא בהם. המערכת בנויה על LlamaIndex, אחסון וקטורי ב-ChromaDB, וממשק Streamlit.

## מה במערכת

| רכיב | בחירה | נימוק |
|---|---|---|
| אחסון וקטורי | ChromaDB (מקומי, PersistentClient) | ללא עלות, נלמד בקורס, נשמר על הדיסק |
| ספרייה | LlamaIndex | API גבוה, פחות קוד ידני |
| פיצול הידע | `SentenceSplitter`, 512 טוקנים, חפיפה 50 (10%) | מכבד גבולות משפט ופסקה, בעלות אפס. **לא** פיצול סמנטי (יקר) |
| אמבדינג | `text-embedding-3-small` | זול, איכות טובה, 1536 ממדים |
| מודל תשובה | `gpt-4o-mini`, temperature=0 | מהיר וזול, מתמודד היטב בעברית |
| Top-K | 4 (ניתן לשינוי בממשק) | איזון בין כיסוי לרעש |
| חיפוש | וקטורי או היברידי (וקטורי + BM25), היברידי כברירת מחדל | משלב דמיון וקטורי והתאמה מילולית; בהרצה שנמדדה שתי השיטות השיגו Hit@4 של 100% |
| הרחבת שאלה | קיימת, כבויה כברירת מחדל | קריאת LLM נוספת - כבויה כדי לא להוסיף השהיה |

## מבנה הפרויקט

```
org-rag-bot/
├── config.py            # כל הקבועות במקום אחד
├── ingest.py            # טעינה, פיצול, אמבדינג, שמירה ל-ChromaDB
├── query.py             # רטרייבר, הרחבת שאלה, הרכבת התשובה
├── app.py               # ממשק Streamlit
├── eval.py              # מדידת Hit@K והשוואת קונפיגורציות
├── data/                # שלושת מסמכי הארגון
└── requirements.txt
```

## התקנה והרצה — Windows עם Git Bash

נדרשת התקנת Python 3.11. הפקודות מופעלות מתוך תיקיית הפרויקט.

```bash
py -3.11 -m venv .venv311
source .venv311/Scripts/activate
python -m pip install -r requirements.txt

test -f .env || cp .env.example .env
notepad .env
```

בקובץ `.env` יש להזין מפתח OpenAI תקף ולשמור.
נדרשת יתרת API זמינה; מנוי ChatGPT אינו כולל שימוש ב־API.
אין להעלות את `.env` למאגר הקוד.

לאחר שמירת המפתח:

```bash
python ingest.py --rebuild
python -m streamlit run app.py
```

הפקודה הראשונה בונה את האינדקס ומשתמשת ב־API בתשלום.
אין צורך לבנות מחדש את האינדקס בכל הפעלה.
בהפעלות הבאות, אם המסמכים והגדרות האינדקס לא השתנו, מספיק להריץ:

```bash
source .venv311/Scripts/activate
python -m streamlit run app.py
```

מדידת דיוק:

```bash
python eval.py
```
## תוצאות הערכה

ההשוואה בוצעה עם Top-K=4. התוצאות הבאות התקבלו בהרצה אחת:

| תצורה | Hit@4 (%) | פספוסים | זמן ממוצע בשניות |
|---|---:|---:|---:|
| וקטורי בלבד | 100.0 | 0 | 0.36 |
| וקטורי + הרחבה | 90.9 | 1 | 1.69 |
| היברידי | 100.0 | 0 | 0.23 |
| היברידי + הרחבה | 90.9 | 1 | 1.52 |

בשתי התצורות עם הרחבת שאלה, המחרוזת המצופה "12:00"
לא נמצאה בקטעים שהוחזרו לשאלה על שעת הסגירה בערב חג.

החיפוש הווקטורי והחיפוש ההיברידי השיגו אותו ציון אחזור.
החיפוש ההיברידי היה מהיר יותר בהרצה זו, אך מדידה אחת אינה מספיקה
להוכחת יתרון מהירות קבוע.

במימוש הנוכחי, Hit@4 מודד אם המחרוזת המצופה מופיעה באחד
מארבעת הקטעים שהוחזרו. זו בדיקת אחזור בסיסית: היא אינה
מוודאת שהמחרוזת נמצאה בסעיף הנכון ואינה בודקת את נכונות
התשובה שנוצרה. נדרשת גם בדיקה ידנית של ההקשר והמקורות.
11 שאלות נכללות בציון; שאלת השלילה אינה נכללת בו.

## אמצעים לצמצום תשובות שאינן מבוססות

המערכת משתמשת באמצעים הבאים כדי לצמצם תשובות שאינן מבוססות
על מסמכי הארגון. אמצעים אלה אינם מבטיחים מניעה מלאה של טעויות,
ולכן יש לבדוק גם את התשובות ואת המקורות התומכים בהן.

1. **הנחיה מגבילה** (`SYSTEM_PROMPT` ב-`config.py`): ענה רק מההקשר; אם אין תשובה - אמור זאת במפורש.
2. **`temperature=0`** - תשובה דטרמיניסטית ככל האפשר.
3. **הצגת מקורות** - כל תשובה מגיעה עם שמות המסמכים שמהם נלקחה, ובממשק אפשר לפתוח את הקטעים עצמם.
4. **שאלת שלילה לבדיקה ידנית** — שאלה שתשובתה אינה במסמכים,
   לבדיקת הימנעות מהמצאת מידע. שאלה זו אינה נכללת בחישוב Hit@4.

### בדיקה ידנית של שאלה ללא מידע

נשאלה שאלה על תעריף החנייה בחניון הסמוך לתחנה.
הבוט ציין שאין מידע בנושא במסמכים ולא המציא מחיר.
הבדיקה עברה.

### בדיקה ידנית המשלבת שני מסמכים

**השאלה:** תחנת קטמון סגורה זמנית. איזו תחנה משמשת לה
גיבוי, ובאילו ימים ושעות מתקיימת בה קבלת קהל בשגרה?

**התוצאה:** הבוט השיב שתחנת רוממה משמשת גיבוי,
ושקבלת הקהל בה מתקיימת בימי א׳, ג׳ וה׳ בשעות 8:00–14:00.

**אימות המקורות:** בקטעים שנשלחו למודל נמצאו סעיף 3.3
מנוהל תפעול התחנות וסעיף 3.1 מנוהל זימון התורים.

בסוף התשובה מוצגת רשימת כל מקורות הקטעים שנשלחו למודל,
בשמות קריאים וללא סיומות קבצים. הרשימה עשויה לכלול גם
מסמכים שאוחזרו אך אינם תומכים ישירות בתשובה.

## בעיות שהתגלו במהלך הפיתוח ופתרונותיהן

### בעיה 1 — אי־תאימות בין Python לתלויות

**הבעיה:** התקנת התלויות בסביבת Python 3.13 נכשלה.
גרסת LlamaIndex שנבחרה דורשת NumPy בגרסה נמוכה מ־2,
וניסיון ההתקנה של NumPy 1.26.4 הוביל לבנייה מקוד מקור שנכשלה.

**הפתרון:** נוצרה סביבה וירטואלית חדשה עם Python 3.11.
לאחר המעבר הותקנו התלויות והפרויקט התקדם להרצת האינדוקס.

### בעיה 2 — חבילת קריאת קבצים חסרה

**הבעיה:** הרצת ingest.py נעצרה עם ההודעה:
ImportError: `llama-index-readers-file` package not found.
התקנת רכיב הליבה של LlamaIndex לא כללה את חבילת קוראי הקבצים.

**הפתרון:** הותקנה חבילת llama-index-readers-file התואמת לגרסת
LlamaIndex בפרויקט. יש לכלול את הגרסה שהותקנה ב־requirements.txt.
לאחר ההתקנה נטענו שלושת המסמכים ונוצרו 12 קטעים.

### בעיה 3 — BM25 קיבל מאגר קטעים ריק

**הבעיה:** לאחר טעינת האינדקס מ־Chroma, ה־docstore המקומי היה ריק.
בניית BM25 ממנו גרמה לאזהרות על נתונים ריקים ולשגיאה בזמן השאילתה:
cannot do a non-empty take from an empty axes.
מנגנון try/except סביב האתחול לא פתר זאת, משום שהכשל הופיע בזמן החיפוש.

**הפתרון:** נוספה טעינה של הטקסטים והמטא־דאטה ישירות מהקולקציה
השמורה ב־Chroma. הקטעים שוחזרו לצמתי LlamaIndex והועברו ל־BM25
באמצעות הפרמטר nodes. לא נדרשה יצירה מחדש של embeddings.

**אימות:** הודפס "נטענו 12 קטעים ל-BM25", השאלה על ביטול תור
קיבלה את התשובה המצופה, והרצת ההשוואה הסתיימה בהצלחה.

## הרצות עתידיות שאפשר להוסיף

- הרחבת סט השאלות ל-30 שאלות כדי לקבל מדידה יציבה יותר.
- השוואת `chunk_size` שונים (256 / 512 / 1024) תחת אותו סט בדיקה.
